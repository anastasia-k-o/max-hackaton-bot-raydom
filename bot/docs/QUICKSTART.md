# Быстрый старт

Документ для того, кто впервые открыл этот модуль. Цель — за пять минут
увидеть бота работающим, а потом решать, нужен ли вам настоящий MAX.

Главное, что стоит знать заранее: **чтобы запустить бота и прогнать все
тесты, не нужно ничего** — ни токена, ни интернета, ни базы данных, ни
мини-приложения, ни Core Backend. Токен понадобится только тогда, когда вы
захотите увидеть сообщения в самом мессенджере.

---

## 1. Что установить

| Нужно | Зачем | Проверить |
|---|---|---|
| Go 1.24+ | собрать и запустить | `go version` |
| make | команды проекта | `make --version` |
| curl | дымовые тесты и скрипты | `curl --version` |
| jq | разбор JSON в скриптах | `jq --version` |
| git | забрать код | `git --version` |

Необязательно, но пригодится:

| Что | Для чего |
|---|---|
| python3 | `make smoke-polling` — подменный сервер MAX |
| openssl | диагностика TLS, если будете подключать настоящий MAX |
| gcc | `make test-race` — детектор гонок требует cgo |
| Docker | `make docker-up`, если не хотите ставить Go |

Одной командой на Debian/Ubuntu (Go ставится отдельно, с <https://go.dev/dl/>):

```bash
sudo apt install -y make curl jq git python3 openssl build-essential
```

## 2. Пять минут до работающего бота

```bash
git clone <адрес репозитория>
cd max-hackaton/bot

cp .env.example .env     # значений по умолчанию достаточно
make run
```

В логе должно появиться `http server listening`. В другом терминале:

```bash
curl -s localhost:8080/health | jq
```

Всё. Это полноценный бот: он принимает уведомления, рисует сообщения с
кнопками, разбирает нажатия и передаёт действия дальше. Просто вместо MAX и
вместо Core Backend подключены реализации, которые держат всё в памяти.

### Полный цикл одной командой

```bash
make smoke
```

Скрипт поднимает бота на свободном порту и делает семнадцать проверок:
уведомление принято → сообщение с кнопками отрисовано → нажатие кнопки
разобрано → действие ушло в Core Backend → сообщение заменено и кнопок
действия в нём не осталось. Плюс отказы: неверный ключ, неизвестный тип,
устаревший payload.

Если `make smoke` зелёный — у вас рабочая копия.

## 3. Тесты

```bash
make test         # все тесты
make test-race    # то же с детектором гонок (нужен gcc)
make test-cover   # покрытие, отчёт в coverage.html
make check        # fmt + vet + test — перед коммитом
```

Два дымовых теста стоят отдельно, потому что поднимают настоящий процесс:

```bash
make smoke          # полный цикл через webhook, режим mock
make smoke-polling  # режим long polling против подменного MAX (нужен python3)
```

`make smoke-polling` заслуживает пояснения: он поднимает на localhost
подменный сервер, отвечающий как MAX, и запускает бота в режиме
`MAX_MODE=real` — но с `MAX_BASE_URL`, указывающим на этот подменный сервер.
Настоящий MAX при этом не вызывается, токен не нужен, а проверяется та часть
связки, которую модульные тесты не достают: что процесс стартует, сам ходит
за событиями и корректно останавливается.

Ни один тест не ходит в сеть и не требует секретов.

## 4. Посмотреть, что бот делает

В режиме разработки (`APP_ENV=dev`) бот показывает свою память:

```bash
curl -s localhost:8080/dev/max/messages | jq   # что он «отправил» в MAX
curl -s localhost:8080/dev/core/actions  | jq  # что передал бы в Core Backend
```

Эти маршруты в production не «закрыты», а не существуют вовсе — они не
регистрируются при `APP_ENV=prod`.

### Postman

В `postman/` лежит готовая коллекция и окружение. Импортируйте оба файла,
выберите окружение «MAX Bot — Local» — и получите 27 запросов: все восемь
типов уведомлений, все четыре нажатия кнопок, ошибочные случаи.

Подробности — [POSTMAN.md](POSTMAN.md).

## 5. Подключить настоящий MAX

Это необязательный шаг. Всё выше работает без него.

### 5.1 Токен

Токен выдают организаторы хакатона, **в репозитории его нет и не будет**.
Спросите у команды и вставьте в свой `.env`:

```env
MAX_MODE=real
MAX_BOT_TOKEN=<токен>
MAX_UPDATES_MODE=polling
```

`.env` в `.gitignore`. Не коммитьте его, даже случайно: токен даёт полный
доступ к боту всем, у кого он есть.

### 5.2 Сертификат

MAX использует сертификат УЦ Минцифры России, которого нет в наборе
корневых сертификатов на обычной Linux-машине. Без него соединение не
устанавливается, и бот откажется стартовать с сообщением «TLS-соединение с
MAX не устанавливается».

```bash
bash scripts/max-install-ca.sh
```

Скрипт скачивает корень, проверяет, что скачался именно сертификат, кладёт
его в `certs/` и подсказывает строку для `.env`:

```env
MAX_CA_FILE=certs/russian_trusted_root_ca.pem
```

Важная деталь: сертификат **добавляется** к системному набору и действует
только на соединение с MAX. Системное хранилище не трогается, на вызовы
Core Backend и любой другой HTTPS доверие не распространяется. Проверяется
тестом `TestExtraRootDoesNotLeakToOtherAdapters`.

Если что-то не так: `bash scripts/max-tls-check.sh` — он разбирает цепочку и
говорит, в чём причина.

### 5.3 Почему polling, а не webhook

Webhook требует, чтобы MAX мог постучаться к вам, то есть публичный
HTTPS-адрес. С ноутбука за NAT его нет, и обычный выход — туннель, то есть
сторонний сервис и аккаунт. В режиме `polling` бот сам открывает соединение
к MAX, и входящий адрес не нужен вовсе.

Режимы взаимоисключающие: по схеме MAX метод `GET /updates` предназначен для
бота, **не подписанного** на webhook. Бот проверяет подписки при старте и
предупреждает, если они есть.

### 5.4 Найти бота и проверить токен

```bash
bash scripts/max-info.sh
```

Скрипт печатает имя бота, его `username` и прямую ссылку, плюс список
подписок на webhook. Токен в вывод не попадает.

### 5.5 Отправить себе все восемь уведомлений

Нужен ваш `max_user_id`: напишите боту что-нибудь в MAX и посмотрите в логи
бота — там будет строка с этим полем.

```bash
bash scripts/demo.sh <ваш_max_user_id>
```

Скрипт играет роль Core Backend и шлёт все восемь типов подряд, печатая для
каждого, что должно прийти. Мероприятия взяты из моков мини-приложения, так
что «Открыть афишу» ведёт на существующую карточку, если мини-приложение
запущено и `MINI_APP_URL=https://<хост>/app`. Без мини-приложения кнопка
просто не добавляется.

Обратное направление — что бот передал бы в Core Backend при нажатии кнопок:

```bash
bash scripts/demo.sh --watch
```

Полная инструкция по MAX — [MAX_SETUP.md](MAX_SETUP.md).

## 6. Если что-то не так

**`bind: address already in use`** — порт 8080 занят. Посмотреть кем:
`ss -ltnp | grep 8080`. Либо поставьте в `.env` другой порт: `HTTP_PORT=8081`.

**`make smoke` падает на первом же шаге** — проверьте, что установлены `curl`
и `jq`, и что порт из `.env` свободен.

**Бот стартует, но не отвечает на кнопки в MAX.** Сначала посмотрите режим:
`curl -s localhost:8080/ready | jq .updates_mode`. Если там `polling`, а
события не приходят — почти наверняка у бота осталась подписка на webhook,
проверьте `bash scripts/max-info.sh`. Режимы взаимоисключающие, и при живой
подписке опрос возвращает пустоту без единой ошибки.

**`POST /webhooks/max` отдаёт 404** — так и задумано при `MAX_MODE=real` с
`MAX_UPDATES_MODE=polling`. Секрет в этом режиме не требуется, проверять
подпись нечем, поэтому маршрут не поднимается.

**`401 Unauthorized` от MAX** — токен не принят. Проверьте, что в `.env`
скопирован весь токен, без пробелов и без префикса `Bearer`.

**Уведомление возвращает 400** — бот назовёт конкретное поле и причину в
`error.details`. Чаще всего это `max_user_id` строкой вместо числа: в
контракте это `integer/int64`.

## 8. Две вещи, которые стоит знать до правок

**Бот ничего не решает.** Есть ли места, можно ли записаться, чья очередь в
листе ожидания, разрешена ли отмена — это решает Core Backend. Бот
отображает и передаёт. Если в `internal/app` появляется `if мест > 0`, это
знак, что ответственность уехала не туда.

**Заглушки не вшиты в бизнес-логику.** `MockMAX` и `StubCoreGateway` — это
реализации интерфейсов, выбираемые в одном-единственном месте,
`cmd/bot/main.go`. Ниже по стеку никто не спрашивает «в каком я режиме».
Поэтому переход на настоящий Core Backend — это `CORE_MODE=http` и
`CORE_BASE_URL` в `.env`, а не правка кода.

Проверить первое утверждение можно буквально:

```bash
grep -rl "max-bot-api-client-go" internal/ cmd/
# единственная строка в выводе — internal/maxapi/real/real.go
```
